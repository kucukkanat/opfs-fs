---
title: opfs-fs
description: Durable, transactional workspaces in the browser’s Origin Private File System.
---

`opfs-fs` gives browser applications an asynchronous POSIX-like workspace with durable commits, real hard links and symlinks, plus a first-class `just-bash` integration.

:::warning
OPFS data belongs to the current origin. Use the explicit export/reset APIs for user-controlled portability and deletion.
:::

## Install from GitHub

The repository commits the package's ESM build and exposes it from the Git
dependency root, so install it under its public scoped name:

```sh
npm install @kucukkanat/opfs-fs@github:kucukkanat/opfs-fs#main
```

The `#main` form follows the latest build. Pin a commit for reproducible builds:

```json
{
  "dependencies": {
    "@kucukkanat/opfs-fs": "github:kucukkanat/opfs-fs#9517c13"
  }
}
```

With Bun, use the same dependency specifier:

```sh
bun add @kucukkanat/opfs-fs@github:kucukkanat/opfs-fs#main
```

The import paths are the same for a Git dependency and an npm registry release.
The monorepo layout is an implementation detail; consumers only use the public
package and documented subpaths.

## Open a workspace

```ts
import { openWorkspace } from "@kucukkanat/opfs-fs"

const fs = await openWorkspace({
  name: "agent-workspace",
  root: "/workspace",
})

await fs.writeFile("/workspace/README.md", "# Durable browser workspace\n")
```

Every individual mutation auto-commits. Use `transaction()` when several changes must become visible together.

```ts
await fs.transaction(async (tx) => {
  await tx.mkdir("/workspace/src", { recursive: true })
  await tx.mv("/workspace/README.md", "/workspace/src/README.md")
})
```

For a single browser application flow covering files, bytes, metadata, links, transactions, archive recovery, storage, typed errors, and `just-bash`, see the [complete example](/opfs-fs/complete-example/).
